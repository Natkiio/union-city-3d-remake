# Original game analysis — The Last Stand: Union City

Notes from reading the decompiled ActionScript 2 of the original SWF. Everything here is a *rule or number from the original*, written as a spec for our Godot remake — not a transliteration.

- **Source**: `reference/scripts/scripts/frame_4/DoAction.as` (git-ignored, regenerate with FFDec; see "Reproducing" below). ~36k lines, 667 functions. Line numbers below refer to that file.
- **Data**: `data/original/*.json`, generated by `tools/extract_data.py`. Numbers in this doc come from `data/original/constants.json` unless noted.
- **Confidence**: statements marked **(verify)** were read from code but not confirmed by playing the original.

AS2 note: `random(n)` returns an integer in `0..n-1`. Time is frame-driven at 30 fps.

## 1. Character model

**Attributes** (5): strength, precision, intellect, endurance, luck. Start at 5 each (`attributeBase`), max 20. At creation the player picks a premade (`data/original/pre.json`, 14 backgrounds) or spends 10 points (`attributePointsMax`).

**Skills** (15): blunt, blades, pistols, longGuns, automatics, specialWeapons, traps, sneak, smarts, security, searching, speech, firstAid, fitness, survival. Start at 7 (`skillBase`), max 100. Each skill is tied to an attribute (`skills.json` → `attr`).

**Effective skill** (`adjustedSkill`):

```
adjustedSkill(s) = round( skill[s] + attribute[ skill.attr ] * 1.6 - 5 )
```

(`attributeMod` = 1.6, `attributeBase` = 5). The `- 5` is the constant, not `attributeBase`, so a base attribute of 5 adds 3 (skill 7 → 10) and each attribute point adds 1.6 effective skill to every skill that uses it. Confirmed against `adjustedSkill` in the source (progression workstream).

**Level up**: cap 30. Each level grants **1 attribute point** and **10 skill points** (`playerAttPoints`, `playerSkillPoints`).

**Derived stats**

| Stat | Formula |
|---|---|
| Max health | `round(20 + endurance² + level × 10)` (endurance includes the hunger penalty) |
| Carry weight | `strengthBase × 10` |
| Stamina max | `round(level + endurance + hungerPenalty + adjustedSkill(fitness) + 56)` |
| Stamina regen / tick | `max(0.1, round((endurance + adjustedSkill(fitness)) / 20))`, starts 15 ticks after last use |
| Stamina cost | run 1, shove 1, jump 5; each reduced by `cost/100 × adjustedSkill(fitness)/10` |
| Move speed | base 7.5; `+ fitness × 0.02`; run ×1.5; crouched `/2`; backwards `/1.5`; crouched+backwards `/3`; **−50 when over carry weight** (that penalty looks huge against a 7.5 base — **(verify)** how it's scaled in the movement code) |

**Health has two layers**: `health` (current) and `permHealth` (a ceiling that drops by `damage / 1.85` on every hit taken). Regeneration only restores `health` up to `permHealth`; first aid is what restores `permHealth`. Regen starts 15 ticks after the last hit and adds `healthMax/200 × (endurance + round(survival/5)) / 2` per tick.

## 2. XP and leveling

- XP **resets to 0** on level-up; the threshold is per level, not cumulative: `levelXP = round(20 × L × (5L) / 100) × 100 = 100 × L²` (L1→100, L5→2,500, L10→10,000, L29→84,100).
- Kill XP: `round(baseXP × enemy.xpBonus)`, `baseXP = round(dangerLevel × 5) + 5`. **No kill XP if `player.level − dangerLevel > 4`** (anti-farming).
- Skill-use XP: search `5 + level`, reload `1 + level`, first aid `5 + level`, security `25 + level` (search/aid/security also add `ceil(adjustedSkill(smarts)/30)`). Quests give a fixed amount from the quest definition.
- Death costs `XP / 2`.
- `skillTrack()` counts uses per skill into `<skill>_used` counters, and they are saved and loaded — but **nothing ever reads them**. It's leftover from a use-based skill-growth design. Skills only grow from level-up points (10/level) and books. Don't build a use-to-improve system for parity.

## 3. Combat

All tunables are in `constants.json`.

### Ranged (`applyDamageProjectiles`, `fireWeapon`, `checkMiss`)

1. **Spread** (fireWeapon): `spread° = (100 − S) / 25 × weapon.accuracy + consecutiveRounds / 7`, where `S = rawSkill (+25 crouched, −20 moving, −50 jumping)`. The shot angle is offset by a random amount in `±spread`. Note this uses the *raw* skill, not `adjustedSkill`. Higher `weapon.accuracy` = *worse*.
2. **Miss roll** (player's ranged): miss if `random(1000) < 400 − round(adjustedSkill × 2)`; crouched multiplies the skill term by 1.5. Chainsaw never misses. Enemies use skill 10, companions 30.
   - ⚠ `missChance` is assigned twice in the source (50 at line 26403, 400 at line 26618). Last assignment wins at runtime → **400** **(verify)**.
3. **Damage per round**: `weapon.damage × zoneMod` (head 1.2, chest 1.0, belly 0.8, legs 0.6), minus a random 0–20%.
4. **Armor**: if the target has `armor<Zone>`, damage is multiplied by it (min 1) unless the weapon has `piercing`.
5. **Player skill bonus**: `+ round(0.05 × (adjustedSkill − 50))`.
6. **Crit** (player only): chance below. `×3` damage plus a stumble.
7. **Knockback**: `random(100) < weapon.knockback` → target stumbles.
8. **Damage to player**: `× playerProjDamRed (1.0)`; `permHealth −= round(damage / 1.85)`.
9. Projectile life `= round(1400 / roundSpeed)` frames; speed varies up to −10% per round. Auto-reload is on by default.

### Melee (`applyDamageMelee`)

```
armed:    round(weapon.damage + strength/3) + round(0.1 × (adjustedSkill − 75))
unarmed:  round(1 + strength/5)
shove:    0.5 + (strength/3)/4
then:     − random(0 .. damage/10)        # up to 10% shaved off
          crit  → ×3
          armor → × target.armor<Zone>
          min 1
```

- Knockback stumble distance: `30 + damage + strength + round(adjustedSkill(fitness)/5)`.
- Zombie hits on the player: `zombie.damage` (below), halved while the player is struggling in a grab.
- "Head shots only" mode (a save option): any non-head hit on a zombie does 1 damage.
- **Zombie melee miss** `random(1000) < 100 − round((endurance + luck)/3)` → roughly a 7–9% chance to miss the player **(verify** that this is the zombie attacking, not the player**)**.

### Crit chance (`setCritChance`, `checkCriticalHit`)

```
critChance% = round(luck / 7 + adjustedSkill(weaponSkill) / 11)
crit if random(100) < critChance        # player only
```

### Zombie stats (`zombieHlth`, `zombieDmg`)

```
health = round((9 + dangerLevel) × enemy.healthBonus)
damage = round(7 × ceil(dangerLevel / 10)) × enemy.damageBonus
```

`dangerLevel` is a property of the location/street/building (1–30), not of the player. See §5 for which enemy types appear where.

## 4. Survival (Survivor mode only)

The game has two modes: **Run'n'Gun** (more ammo/weapons, no hunger/sleep) and **Survivor** (hunger + sleep, rarer ammo).

- `hunger` and `sleep` are 0–100 (0 = fine). Each **game minute** both rise by 0.15 → about 11 game hours from 0 to 100 (the `...HoursDegrade` constants are 1, i.e. every minute).
- Above 70, `penalty = round((value − 70) / 3)`. Sleep penalty lowers precision and intellect; hunger penalty lowers endurance and strength (floor 1).
- Food lowers hunger (`food.json`); sleeping lowers sleep by `round(amount × 10)`. State indicators use `round(value / 25)` (0–4).
- Time: `timeScale = 50` frames per game minute (≈1.67 s real, ≈40 min real per game day). Clock starts at 12:00; `gameTime` counts game minutes and starts at 1440.

## 5. Zombie "director" (spawning)

The game paces zombies with a threat budget plus occasional "rushes".

**Per-area budget** (`setMaxThreat`, recomputed on room change):

```
baseThreat  = round(25 × danger + 30)
              −5 per health threshold crossed (<90%, <70%, <50%, <30%, <10%)
              −2 per meds item in inventory
maxZombies  = min(5, round(danger / 2 + 1)),  ceil(/3) in rooms ≤ 600 wide
safehouse / dangerLevel 0 / director break → maxZombies = 0
```

Each living zombie adds `enemy.threat`; a spawn is only allowed if `enemy.threat + currentThreat ≤ threatMax`. Killing refunds that zombie's threat.

**Which enemies can spawn**: pool `zLevelN` for danger N contains every enemy with `enemy.level < N + 4`. So enemies unlock 4 danger levels *before* their listed level. Enemy table (level / health× / damage× / XP× / chase speed / threat):

| Enemy | Lvl | HP× | Dmg× | XP× | Speed | Threat |
|---|---|---|---|---|---|---|
| zombieSlow | 1 | 1.2 | 1 | 1 | 1.5 | 10 |
| zombieFast | 1 | 1 | 1 | 1.1 | 3.4 | 15 |
| zombieSprint | 3 | 1 | 0.8 | 1.1 | 12 | 25 |
| zombieRiser | 6 | 1 | 1 | 1.1 | 3.4 | 15 |
| zombieFat | 7 | 2.5 | 1.5 | 1.2 | 2 | 20 |
| zombieFatSprint | 7 | 2.5 | 1.2 | 2 | 10 | 30 |
| zombiePolice | 8 | 1.3 | 2 | 1.1 | 3.4 | 12 |
| zombieRiotNoHelmet / Riot / RiotShield | 12 / 15 / 17 | 1 | 2 | 1.2 | 2 | 30–35 |
| zombieCrawl | 12 | 1 | 1 | 1.1 | 2.5 | 20 |
| zombieHammer / Cleaver / Hatchet (+Sprint) | 13–16 | 1.3 | 2 | 1.2–1.3 | 3.4 / 12 | 20–25 |
| zombieDog | 14 | 1 | 1 | 1.2 | 15 | 15 |
| zombieArmy / NoHelmet / Sprint | 15 / 17 / 20 | 1 | 2 | 1.2 | 2 / 10 | 30–35 |

(`enemy.json` has the full records, including `startState`, `walkAnim`.)

**Ambient spawns**: while outdoors and `totalZombies < maxZombies`, every ~3rd director tick (`randZomTrigger`) one random pool zombie spawns 50–150 px off-screen on a side the camera isn't against.

**Room-entry spawns**: if you've been away from a room for more than `repopTime` = 90 game minutes (45 outdoors), entering spawns `random(threatMax/10)` zombies (`/3` outdoors), capped at `maxZombies`.

**Rushes** (`directorLoop`): a rush is a burst where zombies also drop in from roofs. A rush can start when `|lastRushTime − gameTime| > rushTimeRange`, `totalZombies < maxZombies`, no break, and not in a safehouse.

```
rushTimeRange = 3 × (30 − level)          # minutes between rushes; lower level = longer gaps
              +10 if last rush was < 30 min ago
              −10 if health ≥ 50% else +10
              −10 if ammo for current weapon > its average magazine else +10
              +1 per enemy currently on screen
rushLength    = min(15, 2 × danger) game minutes
```

**Breaks**: after `numZombiesSinceBreak > level × 3 + random(level)`, the director forces a break of `random((30 − level) × 0.75) + 0.75` game minutes during which `maxZombies = 0`. This is what gives low-level characters breathing room.

**Drops**: up to 2 "dropper" zombies (carry backpacks with loot); one becomes available every `20 − (5 if health ≤ 20%) + random(20/3)` minutes.

> The health check in the rush formula is written `Math.round(health/max) * 100 > 50` — it rounds *before* multiplying, so it is effectively "health ≥ 50%". Kept as a note in case we want exact parity.

## 6. Searching and loot (`searchContainer`)

Containers are defined per room in `data/original/world/l1..l16.json` (street → building → floor → room → `cont<N>` with a fixed `cnt` list). First search of a container builds its contents and saves them; later opens reuse the saved list. Each first search grants search XP and tracks the `searching` skill.

1. Fixed contents (`cnt`).
2. **Junk roll**: 50% chance (`random(100) ≤ 50`) of `round(random(6) − searching/10)` (min 0) items from the room-type junk list (`<roomType>Junk`).
3. **Lucky roll**: chance `(75 + luck×5 + searching×2) / 1000`. On success, 1–2 items of rarity `r = round(random(danger) + 1) + random(luck/4)` (capped at 30) from `rarity<r>` lists.
4. **Cash** (rooms of type `anywhere` only): 33% chance; amount index up to `ceil( (danger × 3.3 + luck) / 1.5 )`.
5. Contents are shuffled.

Containers marked `noJunk` skip steps 2–4.

## 7. Items

All item types are in `data/original/` (`weapon`, `clothing`, `food`, `meds`, `books`, `junk`, `questItem`). Weapons carry: `damage`, `accuracy`, `reloadTime` (frames), `maxAmmo`, `ammoType`, `roundsPerShot`, `roundSpeed`, `knockback`, `recoil`, `weaponNoise` (alerts zombies within `noiseRangeClose/Medium/Long` = 100/300/500 px), `skill`, `weight`, `rarity`. Melee weapons use `skill` of `blunt` or `blades` and have no noise. Ammo is tracked per weapon instance in inventory plus a pool per ammo type.

**Using items** (`useItem`)

| Type | Effect |
|---|---|
| Food (Survivor) | hunger `−(food.bonus + round(adjustedSkill(survival)/5))` |
| Food (Run'n'Gun) | heals health *and* permHealth by the same amount (no hunger); popup shows it `/3` |
| Meds, `health` | heals `round((bonus + adjustedSkill(firstAid)/2) / 100 × healthMax)` to both health and permHealth. Only usable when `permHealth < healthMax`. Bandages 5, pills 15, medkit 30 |
| Meds, `sleep` (No ZZZ) | `adjustVital(sleep, decNeed, 2.5)` → sleep `−25` |
| Books | `+ (book.bonus (=3) + ceil(adjustedSkill(smarts)/33))` skill points to the book's skill, capped at 100. Consumed |
| Clothing / weapons | equip |

**Weapon mods** (`createWeaponMods`, `applyWeaponMods`): the game generates a variant of each eligible weapon as `<ref>_<mod>` (e.g. `glock_scope`). Multipliers, from `constants.json`:

| Mod | Effect |
|---|---|
| stock | accuracy ×0.9 (lower = tighter) |
| scope | accuracy ×0.7 |
| specOps | accuracy ×0.7, noise ×0.3, no muzzle flash |
| suppressed | damage ×0.9, noise ×0.3, no flash |
| extendedMag | magazine ×1.5 |
| military | damage ×1.3, magazine ×1.3 |
| lightened | weight ×0.5 |
| heavy (blunt) | damage ×1.3, weight ×1.4 |
| sharpened (blades) | damage ×1.3 |
| dull (blades) | damage ×0.7, rarity −2 |
| damaged (any) | damage ×0.5, accuracy ×1.4 (worse), rarity −2 |

Positive mods add +2 rarity (rarer drops).

**Drop rates** (percent, per container roll): ammo 40 (×1.4 in Run'n'Gun), food 30, medical 30, clothing 25, weapons 2, cash 33.

**Shops** (`shopSet1..6`, `data/original/world/shopSet*.json`): up to 9 fixed items with a cost each; `discountCost = ceil(cost × (100 − smarts/2)/100)`, so Smarts 100 halves prices.

### Magazines, reserve ammo and reloading (`fireWeapon`, `startReload`, `reloadWeapon`)

- **Two ammo layers.** Each firearm has a loaded magazine, tracked per weapon instance (`inventory[ID].ammo`, up to `maxAmmo`). Reserve ammo is a shared pool per ammo type (`ammo9mm`, `ammo45`, ...). Reloading moves rounds from the pool into the magazine.
- **One round per trigger pull.** `fireWeapon` decrements the magazine once per call. Pellets (`roundsPerShot`, e.g. shotgun 3) are extra projectiles from that one round.
- **Full reload.** `reloadWeapon("full")` tops the magazine up from the pool in one go, or takes what is left if the pool is short.
- **Pump action reload.** Shells go in one at a time (`reloadWeapon("shotgun")` per loop of `pumpAction_loop`). Pressing fire mid-reload raises the pump and interrupts the reload (`setupFireButton`).
- **Auto-reload.** With `autoReload = true` (line 26033), firing an empty gun starts a reload if the pool is not empty. A click with an empty pool plays a dry-fire sound.
- **Reload time.** The reload bar fills across `reloadTime` frames (`reloadBar_OFF`), so the reload lasts about `reloadTime / 30` seconds (**verify**: the arm animation may set the real length).
- **Skill reload (not reproduced).** A keypress inside the target zone (sized from the weapon skill) sets `skillReloaded`, but both branches of the zone check in `skillReload_OFF` reset the bar the same way. Whether it gives any bonus is **(verify)**.
- **Fire rate (not in the data).** A shot is triggered by the fire animation (`<weaponType>_fire`), so the cadence comes from the animation length, not `weapon.json`. Per-type intervals in the remake are placeholders (**verify**).
- **Trigger mode.** Holding fire keeps `firing` true until release. `fireMode = "auto"` (venom only in the table) is the only explicit auto flag; the remake holds to fire only for auto and clicks otherwise (**verify**).
- **Bursts.** `roundsPerBurst` gives rounds per pull for venom (3), M16A2 (3), FAL/hellSlinger (1). Each round in a burst spends one round of ammo (**verify**).

## 8. Zombie AI (`zombieAIRoutines`)

Each zombie is a state machine: `idle` (risers/crawlers start here, lying down), `wander`, `chase`, `grab`, `attack`, `stumble`. Everything is 1-D along the street (x only), with a few px of y jitter.

| Property | Value |
|---|---|
| Sight range | 600 px, × `currentLighting.sightMod` (**0.6 at every hour** → 360 px), ×1.25 with flashlight on. Must be facing the player |
| Sense range | 150 px (behind or in front) |
| Attack range | `random(30) + 45` px, or `enemy.attackRange` if set |
| Wander speed | `wanderSpeed` (0.75 for riser/crawl); chase speed from `enemy.chaseSpeed` |
| Grab range | 65 px |

**Becoming alerted** (`alertedZombie`): roll `random(500) < chance` where chance = `zombie.alertChance` (5; 1000 for some) plus per-event bonus: melee hit +300, gunshot hit +300, sighted +300, sensed +100, gunshot nearby +20, plus `weapon.weaponNoise × 15`. "Seen" always alerts. Alerted → `chase`; riser zombies first play a rise animation. Alerts don't fire while stumbling or attacking.

**Chase → attack/grab**: within attack range, `random(1000) < zombieGrabChance (100)` (10% per tick) and the player is on the ground (not jumping/falling) and not already grabbed → `grab` (if `noGrab` is not set); otherwise `attack`. Attack animations (`attack1/2`, `attack3` vs downed targets) deal damage through the melee hit-test, using `zombie.damage` from §3. Zombies path around obstacles by climbing blocks.

**Special behaviours**: riot-shield zombies randomly pause (`random(1000) < 300`, for 90 ticks); burning zombies take `burnDamage` (10) every 30 ticks; the targeting loop picks the nearest living, non-downed, non-zombie target (`findZombieTarget`, every 30 ticks).

**Stumble** (knockback): moves `stumbleSpeed` (2 px/tick) to a target distance of `30 + damage + strength + fitness/5`, then returns to the previous state. Crawlers and dogs are immune.

### Grab & struggle

On grab the player is locked in place facing the zombie, and a key-mash minigame starts (A / D by side; Q on AZERTY):

```
presses needed = clamp( round(level × 2 − strength × 2), 3, 8 )
```

So strength ≥ level − 1 gives the minimum 3 presses; a weak high-level character needs the maximum 8. While struggling, the zombie bites on its attack animation for normal damage ×0.5 (`struggleDamageMod`). Escaping shoves the zombie back (a 50-damage-distance stumble). Killing the grabber also ends it.

## 9. Day / night

- 28 lighting presets (`world/lightTime1..28.json`) chosen by clock time: dark 00:00–04:00, brightening through dawn (the red-channel brightness rises 20 → ~100 by 09:30), full day 09:30–16:00, then fading from 16:00 to 20:00 (sunset around 17:00–19:30), dark from 20:00. Each preset is an RGB offset applied to the world; indoor rooms apply `lightReduction` (percent).
- The player's flashlight and street lights switch on as the world gets darker (`streetLightBase 65 − redLight`, hidden below alpha 25).
- **Gameplay effect of night is small**: `sightMod` is 0.6 for every preset, so the spawn/AI rules don't depend on time of day. Danger comes from location, not clock. (Our roadmap's "zombies more aggressive at night" is a *new* feature, not parity.)
- Brightness setting adds `setting × 4` to every channel (min 5).

## 10. Locks and security

- **Doors**: some doors need a key (`needsKey`); a `questItem` with a matching `door` unlocks and is consumed. Otherwise the lockpick minigame opens with that door's `lockDiff`.
- **Container locks**: same minigame, or "force" (not for door locks or keyed locks).
- **Difficulty → required skill**: very easy 15, easy 30, normal 45, hard 60, very hard 75. Pins: 1, 2, 2, 3, 3 by difficulty (the loop indexes from 0, so the count shown may be one more — **(verify)**). Effective difficulty label comes from `adjustedSkill(security) − required`.
- **Pin sweet spot** half-width = `min(10, adjustedSkill(security) / 5 × k)`, `k` = 1.65 / 1.4 / 1.15 / 0.85 / 0.625 by difficulty; spot position is random, nudged by luck.
- **Force lock** chance: `min(95, round((adjustedSkill(security) + luck) × k))`; roll `random(100)+1 ≤ chance`. Success: opens and searches (security XP). Failure: the lock is **permanently broken** (`_br` flag).

## 11. Quests, NPCs, story

Data: `quest.json` (39), `npc.json` (59), `trig.json` (55 scripted triggers). Quest types: `triggered` (14, advanced by trigger/cutscene), `talk` (10), `fetch` (10, hand over `itemReq` items), `kill` (1). Rewards are XP (50–1250) plus optional items, a companion (`follower`/`partner`), or cash.

**Main storyline** (player searches for their partner), in order: 900 *Breaking Through* → 901 *Get Home* → 902 *Clues* → 903 *Hospital* → 904 *Searching* (talk to Shenice) → 905 *Get to Stadium* (1000 XP) → 906 *Registration* → 907 *Relocated* → 908 *Disappeared* → 909 *Maintenance Room* → 910 *Talk to Barry* → 911 *Conspiracy Theory* (1000 XP) → 912 *Theory Proven* → 913 *Another Castle* → 914 *Break Out* → 915 *Alive* (fetch HERC key; reward: partner joins) → 916 *Seabound* → 917 *Military Base* → 918 *Explosive Components* (C4 + blasting cap + timer → XM8 spec-ops) → 919 *Tear it down*. Triggers drive cutscenes (13), `startEndingRush`, `unlockEndLoc`, and `showEnding`.

**Side quests** (fetch/talk): Ed/Ray bolt cutters (001–004), Hank's rifle (002; Hank becomes a follower), Darnel's crafting quests (006–008: heavy pipe, spiked board, suppressed PPM9), Kelly's glasses (011; follower), Jeb's mechanic (015: $500), Lisa/Terry (016: hellSlinger), Phillip's blood samples (017: doctor's office key), Fred's "kill 3 zombies" tutorial (500).

Quests can also **unlock map sections** (`unlocks`) and change NPC states (`changeState*` fields). NPC records carry appearance (clothing fields), dialogue tree by `state`, a weapon, and `enemy`/friendly flags; a handful (`Jeb`/`JebEnemy`, `Paul`/`PaulEnemy`, `Jane/Shawn/Dana` sacrifice and wall variants) are scripted story beats.

> Quest and NPC text is built by concatenating player-sex lookups (`_root[player.sex + "PartnerName"]`, `player.lastName`…). The extractor turns these into `{"template": "…{PartnerName}…", "placeholders": ["PartnerName", …]}`. Consumers fill the placeholders from player state; the JSON never guesses names. The only `$expr` nodes left are `npc.Partner.skinColour` and `npc.PartnerDocks.skinColour` (bare `player.skinColour`, a value rather than text).

## 12. World map

- 16 explorable **sections** (`world/l1..l16`) arranged on a map; the map has 17 slots. The player travels by clicking a section; **travel time = `round(manhattanMapDistance / 200)` game units of time** passed through `sleepWait`, so crossing the map costs time (and hunger/sleep).
- Sections unlock via quests (`unlockAreas`), not by distance.
- **Danger levels** (drive §3 stats and §5 spawns): section 16: 1, 9: 4, 13: 7, 12: 9, 5: 10, 15: 10, 11: 11, 6: 16, 14: 20, 7: 25 (end area). Sections 2, 3, 4, 8, 10 are small and have no danger value (story areas). Uptown (section 1) is built from 7 street blocks.
- Hierarchy inside a section: street → building → floor → room, with doors, stairs, `dropFloor`, safehouse flags, and room `type` (selects the junk list) — see `world/l*.json`.
